## 1. 基本信息

### 1.1 项目名称

**MQTT 权限迁移审计器（MQTT Permission Auditor）**
副标题：以实际送达为证据的 Mosquitto → EMQX 文件 ACL 迁移三态验收

### 1.2 参考方向（可多选）

按主办方方向列表勾选，建议组合（对不上的以官方选项为准）：
- 智能体应用 / Agent 工程（核心：Agnes 在 AGH 内自主规划-调用-解释-复测）
- 网络安全 / 安全运维（IoT 消息中间件权限迁移验收）
- 软件测试与验证 / DevOps 工具（三态判定 + 可复现测试证据）

### 1.3 项目摘要（约 300 字，可直接粘贴）

> Mosquitto 迁移到 EMQX 时，两套 Broker 的 ACL 语义与规则顺序不同，逐行比对配置既不能证明权限没有扩大，也不能证明业务必需路径未受损。本项目把"迁移是否仍满足业务要求"变成可复核的证据问题：在本地隔离的固定镜像 Broker（Mosquitto 2.1.2 / EMQX 6.3.1）上，用独立见证账号验证每条消息是否**实际送达**，把每个检查判为通过、失败或无法判定，并分别报告权限扩大、业务受损、业务要求符合性三个维度；拒绝判定只认协议级证据（SUBACK 0x80），"收到 PUBACK 但未送达"与连接层拒绝一律保留为无法判定。核心验证器零运行时依赖、可独立使用；比赛闭环由 AGH 宿主中的官方 Agnes 模型完成——它自主规划并按序调用受控审计工具（准备、执行、复读），基于结构化返回解释三态结论，并在要求下安排局部复测、核对判定是否变化。真实会话已完整跑通：全量 8 检查 205 条连续事件判定 overall=fail（c3 目标端送达违反"仅 ops-admin 可发布"的业务要求），c3 局部复测判定不变且明确不冒充全量通过；82 项自动化测试全部通过。

### 1.4 问题来源与目标（约 200 字，可直接粘贴）

> 来源：IoT/运维场景中 MQTT Broker 迁移常见，但 ACL 文件语法、默认授权链、规则顺序在 Mosquitto 与 EMQX 间差异显著。实测显示：直接照搬的"朴素迁移"会让源端本应拒绝的发布在目标端实际送达（权限扩大信号），且配置比对与连接成功都无法证明这一点；反之，迁移遗漏会静默破坏业务必需的订阅。目标：给出一个确定性、可复核、证据分级的迁移验收方法与工具，让"通过/失败/无法判定"各自有明确的协议证据边界，并把规划、执行、解释、复测整个验收过程交给 AGH 中的 Agnes 模型按受控工具完成，全程可导出轨迹审计。

## 2. 技术信息

### 2.1 AGH 作用（可直接粘贴）

> AGH（Agnes Harness）是整个验收闭环的宿主：项目以插件 mqtt-audit-tools@0.3.0 接入，注册 4 个受控工具（mqtt_audit_list_cases / mqtt_audit_prepare_run / mqtt_audit_run_check / mqtt_audit_read_result，另有默认关闭的可选建议工具 mqtt_audit_plan_next）、一个会话 Skill（mqtt-migration-audit，用户只说目标即可）和右栏"过程面板"（双端拓扑、实时事件流、历史回放、复测对比、独立健康监测）。比赛任务的核心规划、工具调用、结果解释与复测安排全部在 AGH Web 会话内完成；插件不提供 Shell、任意路径读取、任意网络访问或模型调用，工具只接受固定案例集与固定本地实例标识，面板发起/复测也经由会话 prompt 入口。会话轨迹可用官方 `agh export` 导出完整审计。

#### 口语版（推荐）

**提示词 A（全量验收）：**

```text
帮我把本地这套 Mosquitto 迁到 EMQX 的权限配置验收一下。用你那套 MQTT 审计工具，固定的案例全都跑一遍，最后跟我说清楚：有没有权限被放大、业务有没有受影响、哪些要求没达标，证据分别是什么；说不清楚的就说说不清楚，别替我下结论。顺带把运行的 runId 给我，我回头要查。全程就用这个插件，别碰其他东西。
```

**提示词 B（c3 局部复测，在 A 之后发送）：**

```text
刚才那轮里我最不放心的是 c3，你单独把它再复测一次，看看结论跟刚才一不一样。这轮就测 c3 一个，别重跑其他的；测完说清楚这次复测能说明什么、不能说明什么。
```

**提示词 C（可选收尾，最简目标句，演示 Skill 入口）：**

```text
验收本地 Mosquitto 到 EMQX 的 ACL 迁移，说明风险和证据。
```

口语版容错提示（录制时如遇，自然追问一句即可，不要剪掉，反而体现真实交互）：
- 模型漏了复读结果或没给 runId →「再用 read_result 把最终报告读一遍，runId 也贴给我」；
- 复测没关联上一轮 →「记得挂到上一轮的 runId 下面做局部复测」；
- 模型想重跑全量 →「不用全量，就 c3 这一个」。


**提示词 B'（c3 局部复测；`<RUN_ID>` 替换为 A' 实际返回的全量 runId）：**

```text
请在同一 AGH 会话内只复测上一轮 <RUN_ID> 的 c3。使用 mqtt_audit_prepare_run，参数 caseId=migration-baseline、instanceId=local-isolated、parentRunId=<RUN_ID>、checkIds=[c3]；随后以新 runId 调用 mqtt_audit_run_check，再用新 runId 调用 mqtt_audit_read_result。只使用这三个 MQTT 插件工具；不要调用 Jev、Shell 或访问其他目标。说明 c3 原轮与复测的判定是否变化，明确局部复测不能证明 c1-c8 全量通过。
```
