## 总原则

- 技术栈：Node 24（本机 `v24.21.0`）+ JavaScript ESM；包管理器在阶段 2 初始化仓库时确定并锁定，不引入 Python 运行时。
- 共用一套确定性 [core](../../core/README.md)：权限判定只由确定性代码与本地 Broker 实际观测支撑；模型只负责规划、选用工具、解释反馈和安排复测，见 [架构](../architecture.md)。
- 三态结论：单项结果为"通过 / 失败 / 无法判定"。超时、连接失败、证据缺失和不支持的语法不得计为拒绝或通过。
- 首版只使用固定合成案例（见案例矩阵）；CLI 自定义本地 ACL 文件输入放在赛后阶段。
- 仅使用本地隔离 Broker 与合成数据；插件不提供任意 Shell、任意路径读取、任意网络访问或任意模型调用，也不持有模型 Key。
- AGH 真实接入只能以实际会话中的工具调用事件与结构化返回验收；本地模拟或自然语言复述不作数。
- 时间线按 [比赛要求备忘](../competition.md) 倒排：提交截止 2026-10-15 12:00，前 20 名 16:9 PPT 截止 2026-10-19 12:00（北京时间，提交前核对主办方通知）。

### 阶段 0：环境就绪

- 输入：[环境准备方案](environment-setup-plan.md)、[本地部署与验收](../deployment.md)。
- 输出：两个固定摘要的本地 Broker、健康检查与清理记录、环境版本记录。
- 验收门槛：环境方案"验收门槛"一节全部满足。
- 交付材料：命令与输出记录、镜像摘要与许可结论、未决问题清单。

### 阶段 1：ACL 差异复现

- 输入：阶段 0 环境、[调研](../research.md)提出的规则优先级假设。
- 输出：最小合成 ACL 在两端的实际行为矩阵（允许、拒绝、告警、日志）；Mosquitto 2.1.2 对 `acl_file` 的接受度记录；EMQX 6.3.1 文件授权语法、认证与未命中授权链行为记录。
- 验收门槛：每条行为观测都有发布/订阅协议回执、对端证据或 Broker 日志佐证；假设被证实或证伪都如实记录，不预设结论。
- 交付材料：差异复现记录（配置、身份、主题、命令、观测摘要）；对 core 数据结构与案例矩阵的修正建议。

特别说明：Mosquitto 文档所述 deny 优先与 EMQX 文档所述自上而下命中即停，只是待本地复现的假设；认证方式、授权链配置、未命中策略与 Broker 版本都可能改变结果。若阶段 1 证伪"宽泛允许先于具体拒绝造成权限扩大"，则调整案例矩阵并把真实差异形态写回 [调研](../research.md)，不硬套原假设。

### 阶段 3：AGH 插件

- 输入：阶段 2 的 core 接口、[插件目录说明](../../plugins/agh/README.md)、固定版本的上游[后端插件教程](https://github.com/AgnesAI-Labs/agnes-harness/blob/c4efd170547a225890664c1c186a7347399b53e0/docs/develop/backend.zh-CN.md)与[插件管理指南](https://github.com/AgnesAI-Labs/agnes-harness/blob/c4efd170547a225890664c1c186a7347399b53e0/docs/guide/packages.zh-CN.md)。
- 输出：AGH 后端工具插件，注册三个受控工具：
  - `list_cases`：返回可运行案例的 id 与摘要；

## 首版案例矩阵（固定合成案例）

身份固定为三个合成用户（如 `device-sensor`、`ops-admin`、`guest-ro`），主题使用固定合成前缀（如 `factory/`、`factory/admin/`、`telemetry/`）。下表 ACL 形态是合成设计，实际行为以阶段 1 复现结果为准：

| 案例 | 源端（Mosquitto）形态 | 目标端（EMQX）形态 | 独立业务要求 | 验证点 |
| --- | --- | --- | --- | --- |
| C1 正常允许 | `device-sensor` 可发布 `telemetry/#` | 同样允许 | 业务必需发布必须送达 | 两端允许且消息实际送达 |
| C2 正常拒绝 | `guest-ro` 不得发布 `factory/#` | 同样拒绝 | 禁止必须保持 | 两端拒绝且留有拒绝证据 |
| C3 权限扩大 | 允许发布 `factory/#` 且拒绝 `factory/admin/#` | 迁移后形成先宽泛允许、后具体拒绝的顺序 | `factory/admin/#` 仅 `ops-admin` 可发布 | 目标端是否把源端拒绝翻成允许（待复现假设） |
| C4 业务受损 | `ops-admin` 可发布 `factory/cmd/#` | 迁移遗漏该主题授权 | 业务必需主题必须可用 | 目标端拒绝导致业务受损失败 |
| C5 Broker 不可用 | 正常案例 | 停止目标容器再执行 | 同对应正常案例 | 结论为"无法判定"，不得记为拒绝或通过 |
| C6 恢复复测 | C5 恢复后重跑 | 同 | 同 | 复测结果与首次正常运行对比，留轨迹差异 |

矩阵范围声明：只声明覆盖上述身份、主题、动作组合与所列版本；通配符语义、规则顺序、默认决策等边界按阶段 1 实测写入报告；不宣称全主题或全部身份空间等价。预期结果全部来自独立业务要求，不由待测实现自行生成。

## 结果模型与汇总

- 单项三态：通过 / 失败 / 无法判定；无法判定必须写明来源（超时、连接失败、证据缺失、不支持语法、服务未就绪）。
- 维度汇总：权限扩大（任一案例观测到源端不允许而目标端允许即标记存在）、业务受损（任一业务必需项在目标端被拒即标记存在）、业务要求符合性（对照独立要求逐项判定；迁移前后同样不满足也算失败）。
- 总结论取最坏状态：失败 > 无法判定 > 通过；已知失败不被未知项冲掉，未知项不默认通过。
- 汇总报告附范围声明：两端版本与镜像摘要、身份与主题清单、案例列表、未覆盖项与不支持语法。

## 风险与未决

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| EMQX 6.x 为 BSL 1.1 许可 | 多节点需许可 Key，分发受限 | 仅本地单节点测试；必要时评估退回 5.8.x（Apache 2.0） |
| Mosquitto 2.1 弃用 `acl_file` | 首场景配置方式变化 | 阶段 1 实测接受度；必要时 2.0.x 对照并记录 |
| Docker Desktop 无法启动 | 环境批次延期 | 按环境方案替代路线：WSL 2 内 Engine 或本地 Linux 主机 |
| 保留环境旧插件干扰 | 工具事件混淆 | 接入批次前核验并排除，只记录事实 |
| 截止时间紧（10-15） | 阶段压缩 | 比赛优先固定夹具 MVP；自定义输入留在阶段 6 |
| 优先级假设被证伪 | 案例矩阵调整 | 阶段 1 输出修正后的矩阵再进阶段 2 |
