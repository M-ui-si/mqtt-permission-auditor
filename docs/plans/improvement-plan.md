# MQTT Permission Auditor 改进计划

更新日期：2026-10-13。状态：方案已记录，以下新增能力尚未实现或验收。

## 目标与依据

根据用户转述的官方关注点，补强递归 RS、快速决策、经验改进，以及执行过程与结果可视化。本文暂将“递归 RS”理解为：根据执行反馈继续拆解问题、选择下一步验证并调整方案；RS 的正式定义和评分口径仍需对照官方原文，本文不宣称已满足官方要求。

本次只整理方案，不代表已启动功能开发或真实 Agnes 会话。规划、工具选择、反馈处理和复测必须由官方 AGH/Agnes 执行；插件只提供受控工具与确定性证据，不另建模型调度闭环。

## 改进一：让反馈改变下一步行动

以“验收本地 Mosquitto → EMQX ACL 迁移”为总任务，由 Agnes 根据实际观测生成有限的子任务，记录父子关系、状态、证据引用与简短决策依据。

拟演示的流程：

1. 发现固定案例及独立业务要求，提出初始检查计划。
2. 执行检查，发现 c3 目标端禁止主题实际送达，确认该端业务要求失败。
3. 根据反馈选择受控的针对性检查，区分已确认事实、待验证假设和证据不足项。
4. 若获授权修改本地合成配置，在配置实际变更后复测；否则输出候选修复建议和待验证项。
5. 对照前后观测，给出仍存在的失败、未知项与停止原因。

c3 源端未送达仍须判为 unknown，不能据此声称源端拒绝或权限扩大。规则顺序可以作为待验证假设，不能只凭一次送达观测认定根因。重复执行同一全量检查、复读同一报告或增加工具调用次数，本身不构成递归探索。

实现方向：在固定案例和固定本地实例范围内增加受控的检查子集选择能力，明确返回本次覆盖与未覆盖项。任务关系和决策摘要关联实际工具调用及 runId；插件不负责调用模型。设置明确的轮次、时间和无新增证据停止条件。MQTT 3.1.1 发布拒绝的证据限制不能靠无条件重试消除。

验收标准：真实 AGH 轨迹中至少有一次由返回结果触发的后续计划调整，能够回答“哪条反馈导致选择哪项检查”；子任务关联可核查结果，并在证据不足或预算耗尽时诚实停止。这是项目拟定标准，不是已核验的官方调用次数要求。

## 改进二：用可比较的数据证明快速决策

让 Agnes 根据业务风险和当前证据优先选择检查；核心代码继续负责权限判定。尽早发现高风险失败与完成全部验收应分别展示，不能因为部分检查通过就宣布整体通过。

| 拟记录指标 | 定义与用途 |
| --- | --- |
| 首个有效结论耗时 | 从任务开始到出现首个有观测依据的失败或阶段结论，不能用工具启动时间代替 |
| 反馈到下一步行动耗时 | 从工具返回到下一次工具调用开始，观察决策响应时间 |
| 完整任务耗时 | 包括模型等待、工具运行和必要复测，避免只展示局部耗时 |
| 调用与探针数量 | 分别统计模型工具调用和实际检查数量，说明减少了什么工作 |
| 覆盖与结论一致性 | 对比相同必要覆盖范围的失败、未知及业务要求结论，防止用漏检换速度 |

在固定本地镜像、相同合成配置、明确模型版本与相同必要覆盖范围下，对照固定全量流程和改进流程。记录实际重复测量次数及波动；没有明显改善时如实报告，不预设提升百分比。首次发现问题更早，不等于整体任务更快。

验收标准：提供两种流程的原始计时和检查记录，能够复算指标并解释覆盖差异；未经测量不使用“更快”“减少多少耗时”等成果表述。

## 改进三：让已验证经验影响下一次计划

建立受控、结构化的本地经验记录，拟包含：经验 ID、现象、适用的 Broker 版本及配置条件、验证方法、关联检查、观测结果、证据 runId、限制、验证时间和有效状态。候选经验与已验证经验明确区分。

使用流程：首次任务形成候选经验 → 用真实本地观测验证 → 后续相似任务检索 → Agnes 说明匹配条件与采用理由 → 调整检查顺序或验证方案 → 用新的实际观测评价是否有效。

约束：

- 经验只能指导规划，不能把历史 allow、deny 或 pass 直接当作当前权限结论。
- 不把任意报告文本作为可执行指令；只接收受限字段和固定证据引用，不开放任意路径或网络访问。
- 模型总结不能单独将经验标记为已验证，必须有对应观测和明确适用范围。
- 不适用、过期或与新证据冲突的经验必须跳过或失效，并记录原因。
- 经验只含本地合成数据，导出前脱敏，不包含凭据及原始敏感会话内容。

验收标准：演示一次首次任务的经验形成，以及后续独立任务中的真实检索、采用或拒绝；展示经验确实影响了下一步行动，对比耗时、检查数量和必要覆盖。若未带来效率提升，应记录为未观察到改进，不能把“保存成功”包装成学习效果。

## 改进四：可视化完整执行闭环

在现有概览、对照、轨迹基础上，逐步补充以下内容：

| 展示内容 | 数据依据 | 展示边界 |
| --- | --- | --- |
| 总目标与子任务 | AGH 实际任务记录及父子关系 | 不用预制动画冒充实际计划 |
| 执行进度 | 当前会话工具状态、检查覆盖与时间戳 | 工具完成不等于验收通过；工具内部无事件时仅显示工具级进度 |
| 决策摘要 | Agnes 对当前证据和下一步行动的简短说明 | 展示可核查的行动依据，不声称展示模型内部思维过程 |
| 复测前后对照 | 明确配对的两次 runId、配置版本和检查观测 | 不混入其他会话报告，不因后一次无记录而显示改善 |
| 经验命中与效果 | 经验 ID、匹配条件、采用状态和本次验证结果 | 区分候选、已验证、不适用和已失效 |
| 最终结论与限制 | core 的三态报告、覆盖范围及证据引用 | 保留权限扩大、业务受损、业务要求和未知项，不由面板重算结论 |

验收标准：在同一真实 AGH 演示中，用户能够沿“目标 → 子任务 → 工具反馈 → 决策摘要 → 复测对比 → 经验复用”追溯证据；切换会话、工具失败和报告缺失时状态正确。静态预览、安装成功和离线测试只能证明对应实现，不能替代该验收。
